## Current capabilities

- Durable ingestion journals, ordered replay, bounded intake, retries and
  quarantine inspection protect acknowledged log/document work (R01–R09).
- Isolated multi-turn evaluation, held-out fixtures, citation scoring,
  structured traces and recoverable evaluation records are implemented
  (Q01–Q06).
- Named model profiles control generation and validation settings per request.
  Comparisons use a fixed validator, repeated runs, isolated conversations,
  configuration fingerprints and recorded prompt/scorer identities.
- Reports separate correctness, validator acceptance, citation scores, errors,
  latency and available token usage. Explicit gates reject incomplete or
  inconsistent comparisons; no default model is promoted automatically.

The tracker has 15 verified tasks out of 49; Q07 is in progress. Task counts are
not a percentage of production readiness. Identity, storage ownership,
deployment qualification and operational acceptance remain open.

For the next experiment, the existing example candidates are Qwen3.5 4B,
Qwen3.5 9B and Gemma4 E4B with one shared validator. These are configured
candidates, not verified installations or ranked recommendations. Measure peak
memory and cold/warm behavior alongside report latency on the target machine;
the harness does not yet collect host memory automatically. Keep the current
default until a reviewed comparison supports a change.

Model tags are not verified weight identities, a data revision label does not
freeze databases, and judge agreement is not proof of correctness. These are
the most important remaining limitations for the user's model-control and
traceability goals. Shared use also requires the identity and operational gates
in the tracker; passing offline tests alone does not satisfy them.
